## 3. 错误、适用域和关系登记

四项失败均通过统一 `ModelResult` 返回，并由标准错误码层归一化。常用错误码为 `INVALID_INPUT`、`OUT_OF_DOMAIN`、`NUMERICAL_ERROR`；未通过四维资格闸门的工具不会暴露到 LLM function-call 入口。

| ID | 主要真实失败条件 | 依赖与重叠关系 |
|---|---|---|
| F009 | 总水量超出各区上下限总和、分区名重复、权重非正、上下限颠倒、温升非正、投影不收敛 | 依赖 F008；与 F008 构成“总水量→分区水量”；可消费 F005/F007 热需求并向 F011 提供可用冷却信息 |

## 4. 大模型调用契约

发现入口：

```http
GET /api/v1/tools
```

默认只返回 `fully_eligible=true` 的工具定义；每项定义包含 function name、描述、Draft 2020-12 参数 Schema、必填字段、单位、适用边界、来源、版本、依赖与关系。

执行入口：

```http
POST /api/v1/tools/{function.name}/call
Content-Type: application/json

{
  "arguments": {
    "...": "严格按该工具 parameters Schema 提交"
  },
  "options": {
    "validate_boundary": true,
    "return_provenance": true
  }
}
```

调用规则：

1. 路径使用 `function.name`，不是目录 ID；四项 function name 见第 2 节。
2. `arguments` 必须满足工具返回的 JSON Schema，不允许额外字段；数值按字段单位提交。
3. 调用方必须显式提供工况、物性或边界，不把未知数据默认为现场值。
4. 成功结果返回标准状态、`model_code`、输出、边界检查、来源版本与执行追踪；失败返回标准错误码，不伪造数值。
5. 强制路由测试可使用 `/api/v1/experiments/run` 的 `mode="forced"` 与 `model_code`；本波测试使用隔离 HTTP 合约，不调用外部模型提供商。

四个最小 forced-call 冒烟用例保存在 `Tools/benchmarks/llm_tool_call_cases_p1_w16.json`。该文件只验证接口可调用性和确定性结果，不属于正式研究数据集。
