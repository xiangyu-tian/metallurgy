# 冶金专业文献库建设方案

> **依托平台**：钢铁冶金国家重点实验室 — 智能冶金平台 v2  
> **方案日期**：2026-07-23  
> **建设范围**：独立文献数据库、文献管理、检索与对外展示  
> **本期不包含**：AI问答、向量检索、Embedding、RAG及论文全文智能分析

---

## 一、建设目标

在现有智能冶金平台之外，新建一个独立的 PostgreSQL 文献数据库，用于存放冶金领域论文、标准、专利、技术报告等文献数据。

文献库与现有业务数据库进行物理隔离，平台通过专用文献接口读取公开数据，并在以下位置对外展示：

- 统一专业文献中心；
- 5个研究领域专题页面；
- 文献详情页面；
- 首页或相关栏目中的推荐文献区块。

本期重点是形成稳定、清晰、便于维护的工程化文献展示系统，不建设AI问答能力。

---

## 二、建设原则

### 2.1 文献数据独立存储

文献数据不写入现有：

```text
metallurgy
```

业务数据库，也不继续依赖其中的 `metallurgy_v2.knowledge_docs`。

建议新建独立数据库：

```text
metallurgy_literature
```

数据库名称可以根据实际部署规范调整，但必须与用户、模型、实验和热力学数据分离。

### 2.2 独立账号与权限

建议建立两个数据库账号：

| 账号 | 权限 | 使用场景 |
|---|---|---|
| `literature_reader` | 只读 | 对外展示接口 |
| `literature_admin` | 读写 | 后台管理和数据导入 |

对外展示服务不得使用数据库超级管理员账号。

### 2.3 展示与管理分离

- 普通用户只能查询已发布的公开文献；
- 管理员可以新增、编辑、审核、发布和下架文献；
- 草稿、内部和受限数据不得出现在对外接口中；
- 数据库不直接暴露给前端。

### 2.4 元数据优先

本期优先展示：

- 文献题名；
- 作者；
- 作者机构；
- 摘要；
- 关键词；
- 期刊或会议；
- 出版日期；
- DOI；
- 所属研究领域；
- 文献类型；
- 原始来源链接；
- 标准引用格式。

未经授权的论文不在平台保存或提供全文下载，只展示合法元数据、摘要和原始来源链接。

### 2.5 不在Vue源码中维护文献

现有5个研究领域页面作为文献分类入口，论文数据必须通过后端接口动态读取，不能逐篇写入 Vue 文件。

## 三、总体架构

```text
┌──────────────────────────────────────────────┐
│              智能冶金平台前端                 │
│                                              │
│  文献中心 │ 5个专题页面 │ 文献详情 │ 推荐文献 │
└──────────────────────┬───────────────────────┘
                       │ HTTPS / REST API
┌──────────────────────▼───────────────────────┐
│              专业文献服务接口                 │
│                                              │
│  列表 │ 检索 │ 分类 │ 详情 │ 推荐 │ 后台管理  │
└──────────────┬─────────────────┬─────────────┘
               │只读连接          │读写连接
┌──────────────▼─────────────────▼─────────────┐
│      独立 PostgreSQL：metallurgy_literature   │
│                                              │
│ 来源 │ 文献 │ 作者 │ 领域 │ 关键词 │ 附件信息  │
└──────────────────────────────────────────────┘
```

### 3.1 数据隔离边界

| 数据类型 | 存放位置 |
|---|---|
| 用户、登录和权限 | 现有业务数据库 |
| 热力学和专业模型数据 | 现有冶金数据库 |
| 模型执行和实验数据 | 现有模型/实验数据库结构 |
| 论文、标准、专利和报告 | 新建 `metallurgy_literature` |
| 授权文献附件 | 独立受控文件目录或对象存储 |

### 3.2 服务边界

建议第一期继续使用现有后端提供文献 API，但使用独立数据库连接池。

当文献规模、访问量或维护团队扩大后，可以再将文献模块拆分为独立服务。第一期无需额外增加复杂部署单元。

## 四、数据库设计

### 4.1 数据库

```sql
CREATE DATABASE metallurgy_literature
    WITH ENCODING = 'UTF8';
```

进入新数据库后创建专用 Schema：

```sql
CREATE SCHEMA literature;
```

最终结构：

```text
数据库：metallurgy_literature
└─ Schema：literature
   ├─ sources
   ├─ documents
   ├─ authors
   ├─ document_authors
   ├─ domains
   ├─ document_domains
   ├─ keywords
   ├─ document_keywords
   └─ attachments
```

### 4.2 文献来源表

```sql
CREATE TABLE literature.sources (
    source_id          BIGSERIAL PRIMARY KEY,
    source_name        VARCHAR(255) NOT NULL,
    source_type        VARCHAR(32) NOT NULL,
    provider           VARCHAR(255),
    access_url         TEXT,
    license_note       TEXT,
    security_level     VARCHAR(32) NOT NULL DEFAULT 'public',
    is_active          BOOLEAN NOT NULL DEFAULT TRUE,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

`source_type` 建议取值：

```text
journal
conference
standard_platform
patent_platform
internal
manual_import
```

### 4.3 文献主表

```sql
CREATE TABLE literature.documents (
    document_id        BIGSERIAL PRIMARY KEY,
    source_id          BIGINT REFERENCES literature.sources(source_id),
    document_code      VARCHAR(64) UNIQUE NOT NULL,
    title              TEXT NOT NULL,
    title_en           TEXT,
    document_type      VARCHAR(32) NOT NULL,
    abstract           TEXT,
    abstract_en        TEXT,
    journal_name       TEXT,
    conference_name    TEXT,
    publication_date   DATE,
    publication_year   INTEGER,
    volume             VARCHAR(32),
    issue              VARCHAR(32),
    pages              VARCHAR(32),
    doi                VARCHAR(255),
    standard_no        VARCHAR(128),
    patent_no          VARCHAR(128),
    source_url         TEXT,
    citation_text      TEXT,
    language           VARCHAR(16) NOT NULL DEFAULT 'zh-CN',
    security_level     VARCHAR(32) NOT NULL DEFAULT 'public',
    status             VARCHAR(32) NOT NULL DEFAULT 'draft',
    is_featured        BOOLEAN NOT NULL DEFAULT FALSE,
    published_at       TIMESTAMPTZ,
    created_by         VARCHAR(64),
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

`document_type` 建议取值：

```text
paper
standard
patent
report
book
manual
```

`status` 建议取值：

```text
draft
pending_review
published
archived
```

对外接口只查询：

```sql
WHERE status = 'published'
  AND security_level = 'public'
```

### 4.4 作者表

```sql
CREATE TABLE literature.authors (
    author_id          BIGSERIAL PRIMARY KEY,
    author_name        VARCHAR(255) NOT NULL,
    author_name_en     VARCHAR(255),
    institution        TEXT,
    orcid              VARCHAR(64),
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 4.5 文献作者关系表

```sql
CREATE TABLE literature.document_authors (
    document_id        BIGINT NOT NULL
                       REFERENCES literature.documents(document_id)
                       ON DELETE CASCADE,
    author_id          BIGINT NOT NULL
                       REFERENCES literature.authors(author_id),
    author_order       INTEGER NOT NULL,
    is_corresponding   BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (document_id, author_id)
);
```

### 4.6 研究领域表

```sql
CREATE TABLE literature.domains (
    domain_code        VARCHAR(64) PRIMARY KEY,
    domain_name        VARCHAR(128) NOT NULL,
    description        TEXT,
    route_path         VARCHAR(255),
    sort_order         INTEGER NOT NULL DEFAULT 0,
    is_active          BOOLEAN NOT NULL DEFAULT TRUE
);
```

初始化5个领域：

```sql
INSERT INTO literature.domains
    (domain_code, domain_name, route_path, sort_order)
VALUES
    ('basic_principles', '冶金基础原理', '/basic-principles', 1),
    ('steel_metallurgy', '钢铁冶金', '/steel-metallurgy', 2),
    ('non_ferrous', '有色冶金', '/non-ferrous', 3),
    ('energy_restructuring', '冶金能源重构', '/energy-restructuring', 4),
    ('resource_utilization', '冶金资源利用', '/resource-utilization', 5);
```

### 4.7 文献领域关系表

```sql
CREATE TABLE literature.document_domains (
    document_id        BIGINT NOT NULL
                       REFERENCES literature.documents(document_id)
                       ON DELETE CASCADE,
    domain_code        VARCHAR(64) NOT NULL
                       REFERENCES literature.domains(domain_code),
    is_primary         BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order         INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (document_id, domain_code)
);
```

一篇文献可以属于多个研究领域。

### 4.8 关键词表

```sql
CREATE TABLE literature.keywords (
    keyword_id         BIGSERIAL PRIMARY KEY,
    keyword_name       VARCHAR(128) UNIQUE NOT NULL
);

CREATE TABLE literature.document_keywords (
    document_id        BIGINT NOT NULL
                       REFERENCES literature.documents(document_id)
                       ON DELETE CASCADE,
    keyword_id         BIGINT NOT NULL
                       REFERENCES literature.keywords(keyword_id),
    PRIMARY KEY (document_id, keyword_id)
);
```

### 4.9 附件信息表

```sql
CREATE TABLE literature.attachments (
    attachment_id      BIGSERIAL PRIMARY KEY,
    document_id        BIGINT NOT NULL
                       REFERENCES literature.documents(document_id)
                       ON DELETE CASCADE,
    file_name          TEXT NOT NULL,
    storage_uri        TEXT NOT NULL,
    mime_type          VARCHAR(128),
    file_size          BIGINT,
    checksum_sha256    VARCHAR(128),
    access_level       VARCHAR(32) NOT NULL DEFAULT 'restricted',
    can_download       BOOLEAN NOT NULL DEFAULT FALSE,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

附件表只保存文件信息和受控存储位置，不把大型PDF二进制直接存入数据库。

### 4.10 索引

```sql
CREATE UNIQUE INDEX uq_documents_doi
    ON literature.documents(LOWER(doi))
    WHERE doi IS NOT NULL;

CREATE INDEX idx_documents_status
    ON literature.documents(status, security_level);

CREATE INDEX idx_documents_year
    ON literature.documents(publication_year DESC);

CREATE INDEX idx_documents_type
    ON literature.documents(document_type);

CREATE INDEX idx_documents_title
    ON literature.documents USING GIN
    (to_tsvector('simple', COALESCE(title, '') || ' ' || COALESCE(abstract, '')));
```

第一期不创建向量字段和向量索引。

## 五、数据库账号与隔离策略

### 5.1 账号授权

示例：

```sql
CREATE USER literature_reader WITH PASSWORD '通过安全方式设置';
CREATE USER literature_admin WITH PASSWORD '通过安全方式设置';

GRANT CONNECT ON DATABASE metallurgy_literature
    TO literature_reader, literature_admin;

GRANT USAGE ON SCHEMA literature
    TO literature_reader, literature_admin;

GRANT SELECT ON ALL TABLES IN SCHEMA literature
    TO literature_reader;

GRANT SELECT, INSERT, UPDATE, DELETE
    ON ALL TABLES IN SCHEMA literature
    TO literature_admin;

GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA literature
    TO literature_admin;
```

### 5.2 连接配置

后端通过环境变量连接，禁止在代码中硬编码数据库地址、账号和密码：

```text
LITERATURE_DB_HOST
LITERATURE_DB_PORT
LITERATURE_DB_NAME
LITERATURE_DB_USER
LITERATURE_DB_PASSWORD
LITERATURE_DB_SSL
```

建议：

- 对外查询接口使用 `literature_reader`；
- 后台管理接口使用 `literature_admin`；
- 两套连接池分开创建；
- 生产环境密码使用服务器环境变量或密钥管理；
- 数据库仅允许应用服务器和管理网络访问。

### 5.3 数据库备份

文献库独立备份：

- 每日增量或逻辑备份；
- 定期完整备份；
- 附件存储单独备份；
- 数据库备份与附件备份使用同一批次编号；
- 定期验证恢复流程。

## 七、接口契约

### 7.1 对外文献列表

```text
GET /api/v1/literature/documents
```

查询参数：

```text
q
domain
document_type
year_from
year_to
page
page_size
sort
```

响应：

```json
{
  "items": [
    {
      "document_id": 1,
      "document_code": "LIT-000001",
      "title": "文献标题",
      "authors": ["作者A", "作者B"],
      "journal_name": "期刊名称",
      "publication_year": 2025,
      "doi": "10.xxxx/xxxxx",
      "abstract": "摘要",
      "keywords": ["氢冶金", "直接还原"],
      "domains": ["energy_restructuring"]
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 20
}
```

只返回 `published + public` 数据。

对应交互：文献中心列表、搜索和筛选。

### 7.2 对外文献详情

```text
GET /api/v1/literature/documents/{document_code}
```

返回公开元数据、作者、领域、关键词、引用文本和来源链接。

对应交互：文献详情页。

### 7.3 领域文献

```text
GET /api/v1/literature/domains/{domain_code}/documents
```

查询参数：

```text
document_type
featured
limit
```

对应交互：现有5个研究领域页面中的动态文献区块。

### 7.4 推荐文献

```text
GET /api/v1/literature/featured
```

对应交互：首页或文献中心的推荐文献区块。

### 7.5 管理员新增文献

```text
POST /api/v1/admin/literature/documents
```

请求：

```json
{
  "title": "文献标题",
  "document_type": "paper",
  "abstract": "摘要",
  "publication_year": 2025,
  "journal_name": "期刊名称",
  "doi": "10.xxxx/xxxxx",
  "source_url": "https://合法来源地址",
  "source_id": 1,
  "authors": [
    {
      "author_name": "作者A",
      "institution": "单位",
      "author_order": 1
    }
  ],
  "domain_codes": ["energy_restructuring"],
  "keywords": ["氢冶金"],
  "security_level": "public"
}
```

响应：

```json
{
  "document_code": "LIT-000001",
  "status": "draft"
}
```

对应交互：后台文献录入表单。

### 7.6 管理员审核发布

```text
POST /api/v1/admin/literature/documents/{document_code}/review
```

请求：

```json
{
  "action": "publish",
  "comment": "元数据与公开范围检查通过"
}
```

对应交互：后台审核和发布按钮。

### 7.7 管理员更新与下架

```text
PUT  /api/v1/admin/literature/documents/{document_code}
POST /api/v1/admin/literature/documents/{document_code}/archive
```

不建议物理删除已经对外发布的文献，优先使用下架和归档。

### 7.8 错误码

```text
INVALID_INPUT
DOCUMENT_NOT_FOUND
DUPLICATE_DOCUMENT
DOMAIN_NOT_FOUND
SOURCE_NOT_FOUND
ACCESS_DENIED
LICENSE_RESTRICTED
INTERNAL_ERROR
```

## 十、实施阶段

### M1：独立数据库

建设内容：

- 创建 `metallurgy_literature`；
- 创建 `literature` Schema和数据表；
- 创建只读和读写账号；
- 配置独立连接池；
- 建立数据库备份策略；
- 准备数据导入模板。

验收标准：

> 文献数据与现有业务数据物理隔离，对外服务只能通过只读账号访问已发布的公开文献。

### M2：文献接口与后台管理

建设内容：

- 文献列表、详情和领域查询接口；
- 推荐文献接口；
- 管理员新增、编辑、审核、发布和下架接口；
- 文献管理后台；
- CSV或Excel批量导入。

验收标准：

> 管理员可以完成文献录入、审核和发布，公开接口不能查询草稿、内部或受限文献。

### M3：对外展示

建设内容：

- 新增文献中心；
- 新增文献详情页；
- 顶部导航增加文献入口；
- 5个研究领域页面增加动态文献区块；
- 增加推荐、最新和分类展示；
- 完成响应式适配。

验收标准：

> 外部用户可以从统一文献中心或研究领域页面检索公开文献、查看详情并跳转到合法来源。

### M4：数据完善与上线

建设内容：

- 整理首批公开文献；
- 校验DOI、摘要、来源和领域；
- 完成性能测试；
- 完成权限测试；
- 完成数据备份与恢复验证；
- 完成生产部署。

验收标准：

> 文献库具备稳定的公开展示、后台维护、数据隔离、权限控制和持续更新能力。

## 十一、测试与验收

### 11.1 数据隔离

- 文献数据只存在于新数据库；
- 文献服务不使用现有业务数据库账号；
- 对外接口使用只读账号；
- 只读账号不能新增、修改或删除；
- 文献数据库不可用时不影响用户登录和专业模型服务。

### 11.2 数据权限

- 草稿不对外展示；
- 待审核文献不对外展示；
- 内部和受限文献不对外展示；
- 下架文献不可通过详情接口访问；
- 管理接口必须校验管理员身份。

### 11.3 文献功能

- 标题检索；
- 作者检索；
- DOI检索；
- 领域筛选；
- 类型筛选；
- 年份筛选；
- 分页；
- 文献详情；
- 推荐文献；
- 相关文献。

### 11.4 异常情况

- 重复DOI；
- 缺少标题；
- 非法年份；
- 不存在的领域；
- 不存在的来源；
- 无效来源链接；
- 未登录访问后台；
- 普通用户访问管理接口；
- 文献数据库连接失败。

### 11.5 性能

- 文献列表使用分页；
- 常用筛选字段建立索引；
- 摘要列表限制返回长度；
- 推荐文献限制返回数量；
- 后端使用独立连接池；
- 文献库故障不得拖垮主业务服务。

## 十二、本期明确不建设的内容

为控制范围，本期不包含：

- AI文献问答；
- RAG；
- Embedding；
- 向量数据库；
- 向量检索；
- 自动生成文献综述；
- 自动提取论文实验数据；
- 自动抓取第三方网站；
- 普通用户上传文献；
- 未授权论文全文公开下载。

上述能力可在文献库稳定运行后单独立项，不影响当前数据结构和对外展示。

## 十三、对外展示表述

建成后可对外表述为：

> 平台建设了独立的冶金专业文献库，实现论文、标准、专利和技术报告的统一管理。文献数据与平台业务数据隔离存储，支持按研究领域、文献类型、作者、关键词和年份进行检索，并通过统一文献中心和5个研究领域专题页面对外展示。平台同时建立了文献审核、发布、来源追踪和权限控制机制，保证文献数据可持续维护和规范使用。

---

## 十四、结论

本期采用：

> “一个独立文献数据库 + 一个统一文献中心 + 五个研究领域专题入口 + 一个管理员后台”

的建设结构。

该方案重点解决：

- 文献数据与业务数据隔离；
- 文献统一录入和维护；
- 公开内容审核；
- 多条件文献检索；
- 研究领域分类展示；
- 合法来源跳转；
- 后续持续扩充。

现阶段不建设AI问答，优先完成数据库、接口、管理和对外展示闭环，可以降低系统复杂度，更快形成稳定、可展示、可持续维护的工程成果。
