## 2. 核心决策

### 2.1 双层身份，不再把编号等同于实现

以后必须同时维护两种身份：

1. `catalog_id`：表格中的A001～G015等能力目录编号，表示科学能力和路线位置。
2. `tool_uid`：真实实现的不可变身份，表示一个可执行、可验证、可发布的工具。

现有 `model_code` 作为兼容字段继续保留。目录编号冲突时不直接重命名现有代码，也不创建可计数别名；通过 `tool_uid + catalog_id + legacy_model_codes` 建立映射。

### 2.2 两个计数必须分开

- `runtime_tool_count`：通过资格闸门的独立可执行实现数。
- `catalog_coverage_count`：表格120个目录条目中已有等价实现的条目数。

兼容别名、旧编号、展示包装均不计入 `runtime_tool_count`。理论范围不同的真实变体可计入运行时工具数，但不能自动算作目录条目已覆盖。

### 2.3 表格负责“做什么”，资格闸门负责“能不能计数”

表格重新成为工具选择、场景覆盖、优先级和资料源规划的主目录，但表格行本身仍不能计入真实工具数。只有代码、Schema、边界、失败、来源、验证、关系、数据库资格和大模型接口全部通过后才可计数。

## 5. 数据与依赖分类

表格的“参考资料ID”必须拆成四类，不能混用：

1. `SCIENTIFIC_DATASET`：NIST、JANAF、实验数据、TDB、工艺参数集。
2. `SOFTWARE_DEPENDENCY`：SciPy、Cantera、pycalphad、FiPy、FEniCSx、Pyomo。
3. `INTERNAL_DATASET`：DS042等需授权、脱敏和设备/时间边界的数据。
4. `KNOWLEDGE_REFERENCE`：worldsteel流程说明、标准、论文和工艺知识，不直接作为数值结果记录。

工具数据资格仍分为：

- `FORMULA_ONLY`；
- `REFERENCE_DATA_REQUIRED`；
- `PROCESS_PARAMETER_REQUIRED`；
- `MODEL_ARTIFACT_REQUIRED`。

凡是后三类，必须通过Repository查询数据库，并在结果中返回实际使用记录的 `dataset_id/table/record_id/version/source_ref`。数据库无数据时必须真实失败，禁止静默使用Python字典或JSON资产伪装为数据库结果。

### 6.2 调用规则

1. 大模型只能发现 `fully_eligible=true` 的工具。
2. 参数不完整时先追问，不得猜测单位、相态、参考态或炉型。
3. 数据型工具数据库不可用或无记录时返回失败，不转用隐藏常数。
4. 同一任务存在多个模型时，返回模型适用域差异；必要时允许并行调用并比较。
5. 综合工具可调用原子工具，但执行轨迹必须记录每个子调用。
6. 高风险工艺推荐和超适用域结果必须要求人工确认。

### 6.3 标准成功与失败

成功响应必须包含：结果、单位、边界校验、模型版本、实际数据记录、警告和调用链。

失败响应至少区分：

- `INVALID_INPUT`；
- `OUT_OF_DOMAIN`；
- `MISSING_DATA`；
- `DATA_BACKEND_UNAVAILABLE`；
- `DEPENDENCY_UNAVAILABLE`；
- `MODEL_ARTIFACT_UNAVAILABLE`；
- `NUMERICAL_NONCONVERGENCE`；
- `TOOL_NOT_FULLY_ELIGIBLE`。

## 7. 无损数据导入协议

### 7.1 当前停止条件

本机当前未发现 `pg_dump`。数据库服务版本为PostgreSQL 17.10。没有匹配版本的可靠备份客户端和成功备份文件前，禁止执行任何数据库写入。

### 7.2 写入前硬门槛

每次导入必须依次满足：

1. 安装并登记匹配PostgreSQL 17的客户端工具；依赖版本进入项目维护记录。
2. 使用环境变量读取数据库连接，不硬编码主机或IP。
3. 生成带时间戳的自定义格式全库备份和SHA-256摘要。
4. 执行 `pg_restore --list` 验证备份可解析。
5. 在临时恢复库完成至少一次恢复演练；仅有备份文件不算可恢复。
6. 记录生产库表数量、行数、主键范围和关键自然键摘要作为基线。
7. 默认执行 `--dry-run`，输出拟新增、相同、冲突、拒绝数量。
8. 用户明确批准本次数据集和dry-run报告后才允许 `--apply`。

### 7.3 暂存与校验

- 原始数据只进入独立暂存schema或事务内临时表。
- 暂存记录保存导入批次、源行号、原始值、标准化值、单位、自然键、内容摘要和校验状态。
- 单位、参考态、相态、温区、必填来源和许可证任一缺失即拒绝。
- 数据库表中的既有记录不得在暂存阶段更新。

### 7.4 合并规则

- 禁止 `DROP`、`TRUNCATE`、无条件 `DELETE` 和覆盖式重建。
- 科学数据表默认只允许 `INSERT ... ON CONFLICT DO NOTHING`。
- 相同自然键、相同摘要：视为已存在，不写入。
- 相同自然键、不同摘要：进入冲突表并使整个批次失败，不自动更新旧值。
- 如确需修订旧记录，必须采用新版本记录或显式失效旧版本，并单独批准。
- 合并在单一事务、串行化隔离和数据库 advisory lock 下执行；任一验收失败全部回滚。

### 7.5 写入后验收

- 既有表行数不得减少；非目标表行数和摘要不得变化。
- 新增数量必须与dry-run一致。
- 外键、唯一约束、温区约束和抽样公式验证全部通过。
- 新数据必须能被Repository查询并返回记录级溯源。
- 原有回归、当前30准入测试和新增数据库集成测试全部通过。
- 将导入报告、冲突报告、备份摘要和回滚命令归档。
