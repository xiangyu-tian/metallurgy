# 工具调用难度测试体 v1

日期：2026-09-03  
数据集：`metallurgy-tool-orchestration-difficulty-v1`

## 产出范围

本数据集用于研究大模型在不同难度、外部数据依赖和调用策略下的工具替代边界。它测试的是大模型调用编排行为，不是 120 项冶金工具的数值资格复核。

- 基础问题：40 个。
- 难度等级：5 级，每级 8 个。
- 策略运行体：120 个，每个基础问题分别生成 `auto`、`forced`、`plan` 三种条件。
- 代表工具：17 个，覆盖通用计量、热力学、动力学、高炉、传热、炉外精炼和仿真支撑。
- 候选规模扩展：预留 30 / 60 / 100 / 120 四档，本版不展开执行。

## 难度定义

| 等级 | 名称 | 核心能力 | 主要失败模式 |
|---|---|---|---|
| D0 | 知识边界 | 判断无需工具并直接解释 | 过度调用、强制模式诱发无效调用 |
| D1 | 单工具显式参数 | 选择唯一工具并准确抽参 | 绕过工具、选错相似工具、数值漂移 |
| D2 | 歧义、缺参或越界 | 追问、单位检查、适用域判断 | 猜参、静默修复、无依据外推 |
| D3 | 多工具与状态依赖 | 规划、重复工具绑定、结果传递、续跑 | 错序、漏步、重复执行、丢失编排状态 |
| D4 | 对抗与可靠性 | 抵抗错误暗示、越权请求和冲突输入 | 伪造执行、服从错误工具、越权写入或求解 |

## 文件结构

冻结数据集：

`Tools/benchmarks/tool_orchestration_difficulty_cases_v1.json`

生成器：

`backend/scripts/generate-tool-orchestration-cases.js`

结构测试：

`backend/tests/tool-orchestration-corpus.test.js`

每个基础问题包含：

- 问题、场景、问题类型、难度和研究问题标签；
- 是否需要工具、正确工具、禁止工具和期望调用数；
- 标准参数、单位、标准结果断言与容差；
- 计划步骤、依赖关系、追问字段和适用域；
- 干扰项、故障注入描述、评分重点和判定理由；
- 多轮问题额外包含补参内容、预期状态和是否复用编排 ID。

每个 `run_spec.request` 都可直接作为以下接口的请求体：

```text
POST /api/v1/experiments/tool-orchestration
```

## 三种运行条件

1. `AUTO_PRODUCTION`：生产候选集，模型自主判断是否调用以及选择哪个工具。
2. `FORCED_INTERVENTION`：强制主要工具；对 D0 无工具题故意强制最相近工具，用于测量过度调用或无效追问。
3. `PLAN_PRODUCTION`：允许最多六次调用，用于观察规划、依赖、冗余调用和工作流成功率。

`forced` 是实验干预条件，不会改变基础问题的真实工具需求。例如 D0 的正确标签仍是“无需工具”，不能因为强制策略触发调用就把它改标为需要工具。

## 建议评分

每次运行至少记录：

- 工具调用判断是否正确；
- 候选集是否召回全部必要工具；
- 工具选择、调用次数与执行顺序；
- 参数抽取、参数来源和单位是否正确；
- 是否发生猜参、无效调用或重复调用；
- 缺参追问和适用域拒绝是否合理；
- 多工具工作流是否完整成功；
- 补参是否复用原编排 ID，已完成步骤是否重复执行；
- 产品视图是否泄露工具码、执行 ID、版本或调用过程；
- 最终答案准确率、数值误差、延迟和 Token 消耗。

## 生成与校验

在 `backend` 目录执行：

```powershell
npm run generate:orchestration-cases
npm run test:orchestration
```

生成器是数据集的唯一编辑源。修改基础问题后重新生成冻结 JSON，再运行结构测试，避免手工修改造成生成器与数据文件漂移。

## 当前边界

- 本轮只生成测试体并验证结构，没有向大模型批量发送 120 次实验请求。
- 没有重复运行已经通过的 120 项工具资格测试。
- 30 / 60 / 100 / 120 候选规模实验应固定基础问题、模型版本和提示版本，只改变候选暴露规模。
- 故障注入类问题需在后续实验运行器中增加可控 mock 层，不能修改真实工具结果制造故障。
