## 3. 项目三层分解

### 3.1 第一层：真实可执行冶金工具平台

平台目标是逐阶段形成100–120个真实工具。工具数量只能由统一资格闸门计算，Schema卡、别名包装和无数据支撑的数据型工具不得计数。

### 3.2 第二层：功能模块

| 模块 | 职责 | 本阶段产出 |
|---|---|---|
| 数据治理 | 登记数据集、保存专业数据、记录许可与血缘 | 数据集登记契约、数据导入器、完整性报告 |
| 专业Repository | 工具通过统一访问层查询数据，不写SQL、不读取内置科学数据表 | NASA7/Shomate/Reaction Repository |
| 工具资格闸门 | 分开审查代码、数据、接口和验证资格 | 四维资格报告及严格计数 |
| 工具执行 | 参数校验、真实计算、错误和溯源 | `/validate`、`/execute` |
| 大模型调用 | 输出标准function-tool定义和调用规则 | `/api/v1/tools`与调用规范 |
| 测试与验收 | 单元、数学性质、数据库集成和HTTP闭环 | 自动化准入报告 |

### 3.3 第三层：接口单元

#### 数据访问接口

```python
class ScientificDataRepository:
    def get_record(self, query: dict) -> DataRecord | None: ...

class DataRecord:
    dataset_id: str
    table: str
    record_id: str
    version: str
    value: dict
    units: dict
    applicable_domain: dict
    source_ref: str
    checksum: str | None
```

工具不得判断数据库连接细节；Repository负责连接、参数化SQL、相态/温区匹配和溯源。

#### 工具发现接口

```http
GET /api/v1/tools?fully_eligible=true
```

响应中的每项必须是大模型可直接使用的函数定义：

```json
{
  "type": "function",
  "function": {
    "name": "metallurgy_b002_nasa7_properties",
    "description": "查询数据库中的NASA7系数并计算气相物种热物性；仅适用于数据记录覆盖的温区。",
    "parameters": {
      "type": "object",
      "properties": {
        "species": {"type": "string", "description": "带相态物种，如O2(g)"},
        "temperature": {"type": "number", "unit": "K", "exclusiveMinimum": 0}
      },
      "required": ["species", "temperature"],
      "additionalProperties": false
    }
  },
  "model_code": "B002",
  "model_version": "2.0.0",
  "data_ready": true,
  "dataset_ids": ["DS_NASA7_GRI30"]
}
```

#### 工具校验接口

```http
POST /api/v1/models/{model_code}/validate
Content-Type: application/json

{"input": {...}}
```

校验必填参数、类型、枚举、单位、数值范围和声明的适用域；不执行科学计算。

#### 工具执行接口

```http
POST /api/v1/models/{model_code}/execute
Content-Type: application/json

{
  "input": {...},
  "options": {
    "validate_boundary": true,
    "return_provenance": true
  }
}
```

成功结果必须包含真实使用的数据记录：

```json
{
  "status": "success",
  "model_code": "B002",
  "model_version": "2.0.0",
  "output": {...},
  "actual_data_records": [
    {
      "dataset_id": "DS_NASA7_GRI30",
      "table": "metallurgy_v2.thermodynamic_correlation",
      "record_id": "123",
      "version": "GRI-Mech-3.0",
      "source_ref": "...",
      "temperature_range_k": [200, 1000]
    }
  ],
  "boundary_check": {"passed": true, "warnings": []},
  "error_code": null
}
```

数据库无记录、数据版本失效或连接不可用时，数据必需型工具必须返回 `MISSING_DATA` 或 `DATA_BACKEND_UNAVAILABLE`。不得静默使用Python字典、JSON或测试夹具并返回成功。

## 4. 数据资格分类

### 4.1 `FORMULA_ONLY`

全部科学量由调用参数提供，只依赖数学公式、SI定义或少量版本化基本常数。无需数据库专业数据记录，但必须记录公式和常数来源。

### 4.2 `REFERENCE_DATA_REQUIRED`

依赖原子量、物性、热力学系数、反应数据或相图记录。必须：

1. 在 `dataset_registry` 有有效记录；
2. 数据进入专业数据表；
3. 执行时通过Repository实际查询；
4. 返回实际记录ID和版本；
5. 数据缺失时真实失败。

### 4.3 `PROCESS_PARAMETER_REQUIRED`

依赖收得率、热损、氧利用率、铁损或经验参数。参数可以由用户全部显式输入；若工具提供默认值，默认值必须来自版本化数据库参数集并返回参数集ID。

### 4.4 `MODEL_ARTIFACT_REQUIRED`

数据驱动预测工具必须登记训练/标定数据快照、权重制品、代码版本、依赖锁和适用域。只有模型卡而无固定权重不得计数。

### NASA7导入规则

- 一条数据库记录对应一个物种、一个相态、一个温区段和一组七系数。
- `equation_type='NASA7'`。
- `coefficients` 使用命名字段 `a1`–`a7`，不得只依赖数组顺序。
- 1000 K等分段交点必须有确定优先级并通过连续性检查。
- 导入前计算原始文件SHA-256；登记源URL、许可、版本和获取日期。
- 导入后逐条用原始系数复算Cp/H/S，并与Repository输出比较。
- 仓库JSON导入完成后可以保留为审计原件和测试夹具，但生产执行不得直接读取它。

## 7. 四维资格闸门

每个工具分别报告：

1. `implementation_qualified`：独立实现、Schema、单位、失败条件、验证用例通过；
2. `data_qualified`：所需数据集、数据库记录、版本和许可完整；
3. `interface_qualified`：可发现、可校验、可执行，function-tool定义有效；
4. `scientific_validation_qualified`：独立参考或数学性质验证通过。

最终资格：

```text
fully_eligible = implementation_qualified
              AND data_qualified
              AND interface_qualified
              AND scientific_validation_qualified
```

注册中心必须动态报告：

```json
{
  "registered_count": 30,
  "implementation_qualified_count": 30,
  "data_required_count": 14,
  "data_qualified_count": 0,
  "interface_qualified_count": 0,
  "fully_eligible_count": 0
}
```

示例数字只描述整改前预期，不得硬编码；实际返回值由自动闸门计算。

## 8. 大模型调用规则

1. 只向大模型暴露 `fully_eligible=true` 的工具。
2. 模型必须使用工具清单返回的函数名和JSON Schema，不得猜测参数。
3. 所有温度默认要求K；没有Schema声明不得自行换算或补单位。
4. 缺少必填参数时先追问，不得用未声明默认值补齐。
5. 数据型工具返回 `MISSING_DATA` 或 `DATA_BACKEND_UNAVAILABLE` 时，不得伪造数值；可选择有真实关系登记的替代工具。
6. 综合工具依赖的原子工具或数据集不可用时，返回依赖链错误和失败节点。
7. 同一任务存在多个模型时，根据适用域、数据版本和不确定度选择，而不是仅按名称匹配。
8. 每次执行保存工具版本、数据版本、输入、输出、边界警告和实际数据记录。

## 11. 主要风险

- 数据许可允许查询但不一定允许随仓库或数据库再分发。
- 物种命名、相态和参考态不统一会造成“查到错误数据”而非明显失败。
- NASA7分段点优先级不明确会在1000 K选择错误系数。
- 数据库不可用时静默回退会产生不可审计结果，必须禁止。
- 当前数据库连接配置分散，统一前可能出现API和Repository连接不同实例。
- D001/D002参数高度依赖炉型和计量基准，缺少专业复核时不能宣称生产级预测。
- 当前工作树存在大量用户未提交改动，实施时必须持续限制修改范围。

## 12. 停止条件

出现以下任一情况立即停止该波次并报告：

- 数据源许可或来源无法核验；
- 需要执行未批准的数据库迁移或数据写入；
- 导入前后checksum、记录数或系数复算不一致；
- 数据库结构不能表达物种、相态、温区、参考态或版本；
- 新依赖、外部下载或模型权重未获授权；
- 与用户已有未提交改动发生无法安全规避的重叠；
- 资格闸门必须通过硬编码例外才能让工具计数。
